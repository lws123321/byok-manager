# Security

BYOK Manager edits local model configuration and collects no telemetry. Opening the manager, typing a URL, validating a draft and saving it do not contact the provider. The one exception to local-only setup is **Fetch Model List…** (Responses and Chat Completions). Review the model-list URL in the native VS Code confirmation. Only after you explicitly confirm does the extension host send one `GET` to that destination. Listing models does not validate inference access, token limits or capabilities.

Never paste keys into the webview. **Unauthenticated endpoint** sends no key, even if one is pending. Otherwise the extension host sends the pending key as a Bearer credential to the confirmed destination. If there is no pending key, VS Code prompts for a request-only key in a native masked input. This key is never saved or added to the draft, and discovery does not retrieve a key from the vault. To store a key for Chat, use **Enter API Key** and confirm **Save with Backup**. Native secret-handling commands are internal and may change.

Treat configuration backups as sensitive. Exports remove recognized credentials and headers but cannot recognize all possible secrets in custom fields. Use HTTPS and review every endpoint in the confirmation dialog. Do not share logs or screenshots containing credentials. Report potential vulnerabilities privately to the maintainer through the repository's private reporting channel when configured. Do not disclose live credentials in public issues.
